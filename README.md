# CIFAR-10: inductive bias, memorisation and autoencoders

Code, configuration, saved split, logs and report for a three-part CIFAR-10 study:

| Question | Notebook | What it does |
|---|---|---|
| Q1 | `notebooks/Q1_MLP_CIFAR10.ipynb` | (a) why an MLP does poorly: a parameter-matched MLP vs CNN, a fixed pixel permutation and a capacity sweep; (b) memorisation under 40% label noise |
| Q2 | `notebooks/Q2_CNN_vs_MLP_CIFAR10.ipynb` | (a) a fair CNN vs MLP comparison; (b) a fixed pixel permutation; (c) per-image tile shuffling (local vs global structure), with error and confidence analysis |
| Q3 | `notebooks/Q3_Autoencoders_CIFAR10.ipynb` | (a) three conv autoencoders differing only in bottleneck width; (b) a denoising AE evaluated with a fixed CNN; (c) linear/k-NN probes vs reconstruction quality |

All selection uses a 45,000/5,000 stratified split of the CIFAR-10 training set, seeded by the roll number (all digits, in
order). The official test set is loaded once, in the last section of each notebook, after every choice is fixed.
Q2 and Q3 reuse Q1's split, code and trained runs; each notebook ends with a reuse log.

## Repository layout

```
notebooks/            the three notebooks (config cell tagged `parameters` for papermill)
configs/q{1,2,3}.yaml exact parameters used for the reported run
scripts/run_all.sh    runs Q1 -> Q2 -> Q3 with papermill (one GPU)
scripts/make_split.py regenerates the split from the roll number and checks it against the saved one
scripts/check_results.py  checks that results/ is complete and prints headline numbers
scripts/build_report.py   fills the LaTeX report from results/ (numbers, tables, figures, commit hash)
results/              outputs of the reported run (committed; trained checkpoints in */runs/ are not)
  q1_outputs/split_indices.npz   the saved split
  q*_outputs/*.csv|json|png      every reported table, number and figure
  q*_outputs/environment_used.json, pip_freeze.txt  exact software/hardware of the run
  executed/*.ipynb               executed notebooks (complete logs)
  logs/*.log                     papermill console logs (local runs)
report/               CVPR-format LaTeX report (main.tex, sec/, refs.bib)
environment.yml, requirements.txt, requirements.lock.txt (exact versions, written after the run)
```

## Reproduce locally (exact commands)

Requires Linux, one NVIDIA GPU and conda.

```bash
git clone <REPO_URL> && cd <REPO_DIR>
git checkout <COMMIT>                       # the commit printed on page 1 of the report
conda env create -f environment.yml
conda activate cifar10-study
bash scripts/run_all.sh <ROLL_NUMBER>       # ~2-3 h on a T4; writes results/
python scripts/make_split.py --roll <ROLL_NUMBER>   # optional: independent check of the saved split
python scripts/check_results.py
```

Runs are cached in `results/q*_outputs/runs/`, so an interrupted `run_all.sh` resumes where it stopped.

## Reproduce on Google Colab

1. Open each notebook in Colab (*File -> Upload notebook*) and select *Runtime -> Change runtime type -> T4 GPU*.
2. Add a first cell and run it:
   ```python
   from google.colab import drive
   drive.mount('/content/drive')
   ```
3. In the configuration cell, set `ROLL_NUMBER`, and point the folders at Drive:
   - Q1: `OUT_DIR = "/content/drive/MyDrive/q1_outputs"`
   - Q2: `Q1_OUT_DIR = "/content/drive/MyDrive/q1_outputs"`, `OUT_DIR = "/content/drive/MyDrive/q2_outputs"`
   - Q3: `Q1_OUT_DIR = "/content/drive/MyDrive/q1_outputs"`, `OUT_DIR = "/content/drive/MyDrive/q3_outputs"`
4. *Runtime -> Run all*, in the order Q1, Q2, Q3. After each run, save the notebook with its outputs
   (*File -> Download -> .ipynb*). This executed notebook is the run log.
5. Copy into this repository:
   - `q1_outputs/`, `q2_outputs/`, `q3_outputs/` from Drive -> `results/` (**without** the `runs/` subfolders)
   - the three downloaded executed notebooks -> `results/executed/` (keep the file names in `notebooks/`)

## Build the report

```bash
python scripts/check_results.py                       # everything present?
git add -A && git commit -m "Final results" && git push
python scripts/build_report.py --name "<Your Name>" --roll "<ROLL_NUMBER>" \
    --repo "https://github.com/<user>/<repo>"          # reads the commit hash from git
cd report && latexmk -pdf main.tex                     # -> report/main.pdf
```

`build_report.py` defines every number in the report from `results/` and copies the figures. Any value it cannot find
stays a red **??** in the PDF, so check that none remain. The interpretation paragraphs are generated by the notebooks'
pre-registered decision rules; read them and edit the wording in `report/sec/*.tex` if you want, but keep the numbers.
Without a local LaTeX installation, upload the `report/` folder to Overleaf after running `build_report.py`.

**Commit hash.** The hash printed on page 1 is the commit that contains the code, configs and `results/`. Build the PDF
from that commit. If you commit the PDF or `report/generated/` afterwards, the printed hash still identifies the code and
results the report was built from.

## Notes

- **Determinism:** seeds fix the split, initialisations, batch orders, permutations and noise. cuDNN and fp16
  non-determinism means a rerun matches to within the reported seed spread, not bit-for-bit.
- **Not committed:** CIFAR-10 itself (`data/`, downloaded automatically) and trained checkpoints (`results/*/runs/`,
  about 1.2 GB, regenerated by the notebooks).
